# Standard Flowise Agent Tools (Auto-Included)

**Auto-included in ALL Flowise agents built with Context Foundry**

These 2 tools are automatically included in every Flowise agent with the CORRECT Flowise UI JSON structure to provide temporal awareness and real-time information access. They are built-in Flowise tools that work immediately upon import.

## 1. CurrentDateTime

### Purpose
Provides current date and time to help agents evaluate temporal relevance of information.

### Use Cases
- **Search Result Evaluation**: "Is this news article from today or last year?"
- **Deadline Awareness**: "Is this event still upcoming or has it passed?"
- **Time-Sensitive Decisions**: "What's the current business day for processing?"
- **Context Validation**: "Is this data fresh or stale?"

### Configuration

**Tool Type**: Flowise built-in custom tool

**JSON Structure** (Exact Flowise UI format):
```json
{
  "agentSelectedTool": "currentDateTime",
  "agentSelectedToolRequiresHumanInput": "",
  "agentSelectedToolConfig": {
    "agentSelectedTool": "currentDateTime"
  }
}
```

**Note**: Use empty string `""` for `agentSelectedToolRequiresHumanInput`, NOT boolean `false`.

### Setup in Flowise

1. **Verify Tool Exists**:
   - Go to Tools → Custom Tools
   - Look for "currentDateTime" tool
   - If missing, create it:
     - Name: `currentDateTime`
     - Description: "Returns current date and time"
     - Type: JavaScript function
     - Code:
       ```javascript
       return {
         currentDateTime: new Date().toISOString(),
         timestamp: Date.now(),
         date: new Date().toDateString(),
         time: new Date().toTimeString()
       };
       ```

2. **Tool is Auto-Referenced**:
   - Agents generated by Context Foundry include this tool by default
   - No manual configuration needed after import

### Response Format

```json
{
  "currentDateTime": "2025-11-01T22:45:00.000Z",
  "timestamp": 1730500000000,
  "date": "Fri Nov 01 2025",
  "time": "22:45:00 GMT+0000 (UTC)"
}
```

### Example Agent Usage

**Scenario**: Agent evaluating a search result about "latest AI trends"

```
Agent: Let me check the current date to evaluate if this article is recent.
Tool: currentDateTime
Response: {"currentDateTime": "2025-11-01T22:45:00.000Z", ...}

Agent: The article is from October 2025, which is less than 1 month old.
This is current and relevant information.
```

## 2. SearXNG Search

### Purpose
Federated meta-search engine that searches across multiple sources simultaneously for real-time web information.

### Use Cases
- **Real-Time Facts**: "What's the latest news on this topic?"
- **Current Data**: "What's the current stock price?"
- **Trend Research**: "What are people saying about X right now?"
- **Verification**: "Is this information still accurate?"

### Configuration

**Tool Type**: Custom external API tool

**Base URL**: `https://s.llam.ai`

**JSON Structure** (Exact Flowise UI format):
```json
{
  "agentSelectedTool": "searXNG",
  "agentSelectedToolRequiresHumanInput": "",
  "agentSelectedToolConfig": {
    "apiBase": "https://s.llam.ai",
    "toolName": "searxng-search",
    "toolDescription": "Federated web/meta search. Use when you need fresh facts or sources. Provide a natural-language query; returns a ranked, de-duplicated JSON list of result metadata for follow-up browsing and citation.",
    "headers": "",
    "format": "json",
    "categories": "",
    "engines": "",
    "language": "",
    "pageno": "",
    "time_range": "",
    "safesearch": "",
    "agentSelectedTool": "searXNG"
  }
}
```

**Critical Field Names**:
- ✅ `agentSelectedTool: "searXNG"` (capital XNG, NOT "searxng-search")
- ✅ `apiBase` (NOT "baseUrl")
- ✅ `agentSelectedToolRequiresHumanInput: ""` (empty string, NOT `false`)
- ✅ `toolName: "searxng-search"` (lowercase, inside config)

### Setup in Flowise

1. **Create Custom Tool**:
   - Go to Tools → Add Custom Tool
   - Configure:
     - **Name**: `searxng-search`
     - **Description**: "Federated web/meta search. Use when you need fresh facts or sources. Provide a natural-language query; returns a ranked, de-duplicated JSON list of result metadata for follow-up browsing and citation."
     - **Type**: HTTP API
     - **Auth**: None required

2. **API Configuration**:
   ```json
   {
     "baseUrl": "https://s.llam.ai",
     "method": "GET",
     "endpoint": "/search",
     "parameters": {
       "q": {
         "type": "string",
         "required": true,
         "description": "Natural language search query"
       },
       "format": {
         "type": "string",
         "required": false,
         "default": "json",
         "options": ["json", "csv", "rss"]
       },
       "pageno": {
         "type": "number",
         "required": false,
         "default": 1,
         "description": "Page number for pagination"
       },
       "language": {
         "type": "string",
         "required": false,
         "default": "en",
         "description": "Language code (e.g., en, es, fr)"
       }
     }
   }
   ```

3. **Response Schema**:
   ```json
   {
     "results": [
       {
         "title": "Page title",
         "url": "https://example.com/page",
         "content": "Excerpt of page content",
         "engine": "search engine name",
         "score": 0.95,
         "publishedDate": "2025-11-01"
       }
     ],
     "number_of_results": 10,
     "query": "original query string"
   }
   ```

### SearXNG Features

**Federated Search**:
- Searches across multiple engines simultaneously (Google, Bing, DuckDuckGo, etc.)
- Aggregates and de-duplicates results
- Ranks by relevance across all sources

**Privacy-Focused**:
- No tracking or user profiling
- No cookies or JavaScript required
- Open-source and transparent

**Fast Performance**:
- Parallel searches across engines
- Results returned in <2 seconds typically
- Caching for frequently searched queries

## Combined Usage: Temporal Awareness + Real-Time Search

### Workflow Pattern

1. **Agent receives query** requiring current information
2. **Uses currentDateTime** to establish temporal context
3. **Uses searxng-search** to find relevant sources
4. **Cross-references** search result dates with current date
5. **Filters** for recent/relevant results
6. **Provides answer** with temporal context

### Example: "What's the latest on climate policy?"

```
Step 1: Check current date
Tool: currentDateTime
Response: "2025-11-01T22:45:00.000Z"

Step 2: Search for latest climate policy news
Tool: searxng-search

Response: [10 results from various dates]

Step 3: Filter by recency
Agent: Checking result dates against current date (Nov 1, 2025)
- Result 1: Oct 30, 2025 (2 days old) ✓ RECENT
- Result 2: Sept 15, 2025 (6 weeks old) ✓ RECENT
- Result 3: June 2024 (17 months old) ✗ OUTDATED

Step 4: Synthesize answer
Agent: "Based on searches from Nov 1, 2025, the latest developments
in climate policy include... [synthesizes from recent results only]"
```

## Troubleshooting

### Issue: "Tool not found" error on import

**Cause**: Custom tools don't exist in Flowise instance

**Solution**:
1. Go to Flowise UI → Tools → Custom Tools
2. Create `currentDateTime` tool (see setup above)
3. Create `searxng-search` tool (see setup above)
4. Re-import workflow

### Issue: SearXNG returns no results

**Possible causes**:
- Base URL unreachable
- Query too broad/vague
- Language parameter incorrect

**Solution**:
1. Test base URL: https://s.llam.ai/search?q=test&format=json
2. Refine query to be more specific
3. Check language parameter (default: "en")

### Issue: currentDateTime returns stale time

**Cause**: Caching in Flowise

**Solution**:
- Flowise may cache tool results briefly
- If critical, add timestamp to tool call to force refresh
- Or implement tool with explicit cache-busting parameter

## Best Practices

### When to Use currentDateTime

✅ **Use when**:
- Evaluating search result freshness
- Time-sensitive decisions
- Deadline checking
- Temporal context needed

❌ **Don't use when**:
- Historical queries (use explicit date parameters instead)
- Timezone-agnostic operations
- Performance-critical paths (caching issues)

### When to Use searxng-search

✅ **Use when**:
- Real-time facts needed
- Current events research
- Verification of latest information
- Broad web search required

❌ **Don't use when**:
- Domain-specific knowledge available (use knowledge base instead)
- Historical data needed (use databases/archives)
- Precise API data available (use direct API tool instead)

### Combined Usage Best Practices

1. **Always filter search results by date**:
   - Use currentDateTime to establish "now"
   - Compare search result dates
   - Filter for recency threshold (e.g., last 30 days)

2. **Cite sources with temporal context**:
   - "According to TechCrunch (Nov 1, 2025)..."
   - "Latest data as of November 2025 shows..."

3. **Handle missing dates gracefully**:
   - Not all search results have publishedDate
   - Use content analysis to infer recency
   - Warn user if date unavailable
