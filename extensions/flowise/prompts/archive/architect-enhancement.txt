## LLM Chain Configuration

**Optimal Settings:**
```json
{
  "modelName": "gpt-4" or "claude-3-opus",
  "temperature": 0.7,  // 0.0 for factual, 1.0 for creative
  "maxTokens": 2000,   // Limit to prevent runaway costs
  "topP": 0.9,
  "frequencyPenalty": 0.0,
  "presencePenalty": 0.0,
  "timeout": 30000,    // 30 second timeout
  "maxRetries": 3
}
```

**Best Practices:**
- Always set maxTokens to prevent unbounded generation
- Use temperature=0 for classification/extraction tasks
- Implement timeout to prevent hanging requests
- Configure retry logic with exponential backoff
- Log prompts and responses for debugging

**Anti-Patterns:**
- No maxTokens limit (cost explosion risk)
- No timeout (can hang indefinitely)
- Temperature=1.0 for factual tasks (hallucinations)
- Sending entire conversation every time (token waste)

## Agent Executor Configuration

**Supervisor Agent Pattern:**
```json
{
  "agentType": "openai-functions",
  "systemMessage": "You are a supervisor coordinating specialized workers...",
  "maxIterations": 10,
  "earlyStoppingMethod": "force",
  "tools": ["worker1", "worker2", "worker3"],
  "returnIntermediateSteps": true,
  "verbose": true
}
```

**Worker Agent Pattern:**
```json
{
  "agentType": "openai-functions",
  "systemMessage": "You are an expert at [SPECIFIC TASK]. Focus only on this task.",
  "maxIterations": 5,
  "tools": ["specific_tool_only"],
  "returnIntermediateSteps": false
}
```

**Best Practices:**
- Limit maxIterations to prevent infinite loops (5-10 typical)
- Supervisor agents have broad tools, workers have narrow tools
- Use returnIntermediateSteps for debugging
- Clear, specific system messages for each agent role
- earlyStoppingMethod="force" prevents runaway agents

**Anti-Patterns:**
- No maxIterations limit (infinite loops possible)
- Agents with overlapping tool sets (confusion)
- Generic system messages (poor performance)
- More than 5 worker agents (routing errors)

---

## Memory Systems Configuration

**Buffer Memory (Short Conversations):**
```json
{
  "memoryType": "BufferMemory",
  "memoryKey": "chat_history",
  "returnMessages": true,
  "inputKey": "input",
  "outputKey": "output"
}
```

**Summary Memory (Long Conversations):**
```json
{
  "memoryType": "ConversationSummaryMemory",
  "llm": "gpt-3.5-turbo",
  "memoryKey": "chat_history",
  "maxTokenLimit": 2000
}
```

**Best Practices:**
- Use BufferMemory for <10 message exchanges
- Switch to SummaryMemory for longer conversations
- Always set maxTokenLimit to prevent context overflow
- Clear memory between different user sessions
- Store critical info in structured memory (not just chat)

**Anti-Patterns:**
- Unbounded BufferMemory (context window explosion)
- No memory for multi-turn conversations
- Sharing memory between unrelated users
- Not clearing memory when context changes

---

## Tool Integration Patterns

**API Tool Configuration:**
```json
{
  "name": "search_database",
  "description": "Search the product database for items matching criteria. Input should be a JSON object with 'query' and 'filters' fields.",
  "schema": {
    "type": "object",
    "properties": {
      "query": {"type": "string"},
      "filters": {"type": "object"}
    },
    "required": ["query"]
  },
  "timeout": 10000,
  "retries": 2
}
```

**Best Practices:**
- Tool descriptions are clear, specific instructions
- Input schema explicitly defined and validated
- Timeout configured for every external call
- Retry logic for transient failures
- Output sanitized before returning to LLM
- Tool names are action verbs (search_*, create_*, update_*)

**Anti-Patterns:**
- Vague tool descriptions ("useful tool")
- No input validation (garbage in, garbage out)
- No timeout (hangs on slow APIs)
- Exposing internal error messages to users
- Tool names that don't indicate action

## Multi-Agent Flow Architecture

```
┌─────────────────────────────────────────┐
│         Supervisor Agent                │
│  - Routes tasks to workers              │
│  - Aggregates results                   │
│  - Handles failures                     │
└─────────────┬───────────────────────────┘
              │
     ┌────────┴────────┬─────────────┐
     ▼                 ▼             ▼
┌─────────┐      ┌─────────┐   ┌─────────┐
│ Worker  │      │ Worker  │   │ Worker  │
│ Agent 1 │      │ Agent 2 │   │ Agent 3 │
│ (Search)│      │ (Analyze)│  │ (Format)│
└─────────┘      └─────────┘   └─────────┘
```

**Implementation Checklist:**
- [ ] Supervisor has clear routing logic
- [ ] Each worker has narrow, specific role
- [ ] Shared memory for context passing
- [ ] Error handling at supervisor level
- [ ] Maximum 5 worker agents
- [ ] Workers don't call other workers directly

## RAG Flow Architecture

```
┌─────────────┐
│ User Query  │
└──────┬──────┘
       │
       ▼
┌─────────────────────────────┐
│  Retriever Node             │
│  - Vector search            │
│  - Hybrid search (optional) │
│  - Reranking (recommended)  │
└──────┬──────────────────────┘
       │
       ▼
┌─────────────────────────────┐
│  LLM Chain                  │
│  - Context: retrieved docs  │
│  - Task: answer question    │
│  - Cite sources             │
└──────┬──────────────────────┘
       │
       ▼
┌─────────────┐
│  Response   │
└─────────────┘
```

**Implementation Checklist:**
- [ ] Vector store configured and populated
- [ ] Embedding model consistent with storage
- [ ] Chunk size: 512-1024 tokens
- [ ] Top-k retrieval: 3-5 documents
- [ ] Reranking implemented for better relevance
- [ ] Fallback response when no docs found
- [ ] Citations included in response
- [ ] Embedding cache for performance

## Sequential Workflow Architecture

```
Step 1 (Extract) → Step 2 (Transform) → Step 3 (Load)
     ↓                    ↓                   ↓
  Validate           Validate            Validate
     ↓                    ↓                   ↓
  [Error]            [Error]             [Error]
     ↓                    ↓                   ↓
  Retry              Retry               Retry
```

**Implementation Checklist:**
- [ ] Each step has clear input/output contract
- [ ] Output validation before next step
- [ ] Error handling and retry per step
- [ ] State persisted between steps
- [ ] Idempotent operations (safe to retry)
- [ ] Progress tracking for long workflows
- [ ] Rollback capability for failures

## Unit Tests (Node-Level)

**Test Each Node Type:**

```python
# Example: Test LLM Chain node
def test_llm_chain_node():
    # Mock LLM response
    mock_llm = MockLLM(response="Expected output")

    # Configure node
    node = LLMChain(llm=mock_llm, prompt=test_prompt)

    # Test with known input
    result = node.run(input="Test input")

    # Validate output
    assert result == "Expected output"
    assert mock_llm.call_count == 1
```

**What to Test:**
- Node configurations are valid
- Error handling works (timeout, retry)
- Output format matches expected schema
- Edge cases (empty input, special characters)

---

## Integration Tests (Flow-Level)

**Test Node Connections:**

```python
def test_multi_agent_flow():
    # Setup supervisor and workers
    supervisor = create_supervisor_agent()
    worker1 = create_search_worker()
    worker2 = create_analyze_worker()

    # Connect nodes
    flow = create_flow(supervisor, [worker1, worker2])

    # Test with realistic input
    result = flow.run("Find and analyze product X")

    # Validate workflow
    assert "search" in result.intermediate_steps
    assert "analyze" in result.intermediate_steps
    assert result.output is not None
```

**What to Test:**
- Data passes correctly between nodes
- Memory persists across steps
- Error propagates appropriately
- Tool calls happen in right order

## E2E Tests (Real LLM)

**Test Complete Flow:**

```python
def test_rag_flow_e2e():
    # Use real vector store and LLM
    flow = load_production_flow()

    # Test with real query
    result = flow.run("What is the return policy?")

    # Validate result quality
    assert len(result.source_documents) > 0
    assert "return" in result.output.lower()
    assert result.sources_cited == True

    # Check token usage
    assert result.total_tokens < 5000
```

**What to Test:**
- Real LLM integration works
- Costs are reasonable (token usage)
- Response quality meets standards
- Citations are accurate
- Performance is acceptable (<5s)
