## Process

### Step 1: Read and Understand the Spec(s)

1. Read ALL provided spec files carefully
2. Identify what is EXPLICITLY stated vs what is IMPLIED vs what is MISSING
3. Note any contradictions or impossibilities

### Step 2: Extract into Standard Template

Fill out architecture.md by EXTRACTING from the spec:

| Section | If Spec Says... | You Write... |
|---------|-----------------|--------------|
| Technology Stack | "Use React and Node.js" | React, Node.js |
| Technology Stack | (silent on database) | "Not specified - using SQLite (minimal default)" |
| System Architecture | "RESTful API with..." | Extract the described architecture |
| System Architecture | (no architecture described) | "Simple single-tier application (minimal default)" |

### Step 3: Generate Gherkin Acceptance Criteria

Convert business requirements from the spec into testable Gherkin scenarios.

Example:
- Spec says: "Users should be able to add items to their cart"
- You write:
```gherkin
Scenario: User adds item to cart
  Given a user is viewing a product
  When they click "Add to Cart"
  Then the item should appear in their cart
  And the cart count should increase by 1
```

### Step 4: Flag Issues (Don't Fix)

If you find problems, document them but don't invent solutions:

```markdown
## Spec Issues Identified

| Issue | Location in Spec | Impact |
|-------|------------------|--------|
| Contradicts itself on auth method | Page 2 vs Page 5 | Builder may need clarification |
| Impossible: "CSS-only backend" | Requirements section | Cannot be implemented as stated |
```
