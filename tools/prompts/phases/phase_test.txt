TEST PHASE INSTRUCTIONS

**Mission**: Verify the software quality by running tests and analyzing results.

**Step 1: Analyze & Plan (The "Understand" Phase)**

1.  **Read Architecture**: Find testing requirements in `.context-foundry/architecture.md` (or `build-tasks.md`).
2.  **Explore Context**: Use `list_dir` to find test files (`tests/`, `spec/`, etc.).
3.  **Determine Commands**: Identify how to test this project (e.g., `npm test`, `pytest`, `cargo test`) based on the stack.

**Step 2: Execute Tests (The "Test" Phase)**

1.  **Run Tests**: Use `run_command` to execute the identified test commands.
2.  **Capture Output**: Read the terminal output to understand pass/fail status and identify root causes.

**Step 3: Create Report (The "Report" Phase)**

You **MUST** create `.context-foundry/test-report.md` (or the filename provided in your context usually `test-report-{N}.md`).
Your output **MUST** follow this structure to pass validation:

```markdown
# Test Report: {Project Name}

**Date**: {current_date}
**Iteration**: {test_iteration or 0}

## Test Summary
**Status**: {PASSED|FAILED} (CRITICAL: Must be exact string)
**Total Tests**: {count}
**Passed**: {count}
**Failed**: {count}

## Test Detail

### Command: {Test Command}
**Status**: {PASSED|FAILED}
**Output**:
```
{Relevant log snippets}
```

## Failures (Required if Status is FAILED)

### Failure 1: {TestName}
**File**: {path/to/file}:{line}
**Error**: {Error message}
**Root Cause**: {Detailed analysis of why it failed}
**Suggested Fix**: {Specific instructions for the Architect/Builder}

## Conclusion
{Summary of next steps}
```

**Step 4: Verify Output (The "Check" Phase)**

1.  **File Existence**: Verify the report file exists.
2.  **Content Check**: Ensure the file contains the string "PASSED" or "FAILED" (case-insensitive checking, but uppercase preferred).

**DONE**: Your process exits. If tests failed, the Architect will read your report to plan fixes.
