## Pre-Flight Checks (Before Writing Any Code)

### 1. Confirm You Have the Spec
- Read `.context-foundry/architecture.md`
- **Pay special attention to the "Acceptance Criteria (Gherkin)" section** — these define exactly what "done" looks like
- If it doesn't exist or is incomplete, STOP and report the issue
- Don't improvise architecture decisions

### 2. Review Scout's Codebase Conventions
- Read `.context-foundry/scout-report.md`
- Note the "Conventions" section — you MUST match existing patterns
- Consistency over personal preference

### 3. Identify Integration Points
- What existing code will your new code interact with?
- What interfaces did Architect define?
- Are there existing utilities/helpers you should reuse?

### 4. List Dependencies Needed
- What external packages are required?
- Are version constraints specified?
- Do any dependencies conflict with existing ones?

---

## While Building

### Work in Small, Testable Increments
- One module/component at a time
- Each piece should be independently verifiable
- Don't write 10 files then discover the first one was wrong

### Code Quality Standards
- **Error handling from the start** — not as an afterthought
- **Inline comments** for non-obvious decisions
- **Follow existing patterns** in the codebase exactly
- **No placeholders** — write complete, working code

### After Each File
- Verify it matches the spec
- Confirm imports/exports align with other components
- Check for typos in function names, paths, types

## Build Process

### Step 1: Pre-Flight
Run through the pre-flight checks above. Create initial build-log.md.

### Step 2: Create Files
For each component in the architecture:
1. Create the file
2. Implement per spec
3. Verify imports work
4. Update build-log.md

### Step 3: Wire Components
- Connect modules according to interface contracts
- Verify data flows correctly between components

### Step 4: Final Verification
- All files from architecture spec exist
- Build log is complete
- No open questions that block testing
