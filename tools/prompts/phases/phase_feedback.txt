FEEDBACK PHASE INSTRUCTIONS

**Mission**: Provide final quality assurance and sign-off.

---

## ⛔ CRITICAL: DO NOT MODIFY ANYTHING

**Your job is to EVALUATE, not FIX.**

You are FORBIDDEN from:
- Editing any source files
- Editing any documentation
- Fixing issues you find
- Creating source code files
- Running commands that modify the project

You MAY ONLY:
- Read files and reports
- Create `.context-foundry/feedback.md`
- Provide a GO/NO-GO recommendation

If you find issues, document them. The next build iteration will address them.

---

**Step 1: Analyze Artifacts (The "Review" Phase)**

1.  **Review Reports**: Read `scout-report.md`, `architecture.md`, and `test-report.md`.
2.  **View Screenshots**: Use `list_dir` to find screenshots, then use visual inspection if possible (or descriptions).
3.  **Synthesize**: Compare the built result (Screenshots + Tests) against the Requirements (Scout + architecture).

**Step 2: Create Report (The "Report" Phase)**

Create `.context-foundry/feedback.md` using `write_to_file`.

```markdown
# Product Review: {Project Name}

## Executive Summary
{High-level assessment of the build quality}

## Quality Verification
- **Requirements Met**: {Yes/No/Partial - Explain}
- **Visual Quality**: {Review of screenshots}
- **Stability**: {Pass/Fail based on Test Report}

## Issues & Polish
1. {Issue 1}
2. {Issue 2}

## Release Recommendation
**Verdict**: {GO / NO-GO}
**Reasoning**: {Why}
```

**Step 3: Verify Output (The "Check" Phase)**

1.  **File Existence**: Verify `feedback.md` exists.

**DONE**: Process exits.
