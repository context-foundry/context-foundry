FEEDBACK PHASE INSTRUCTIONS

**Mission**: Provide final quality assurance, sign-off, and capture learnings for future builds.

---

## ⛔ CRITICAL: DO NOT MODIFY SOURCE CODE

**Your job is to EVALUATE and CAPTURE LEARNINGS, not FIX.**

You are FORBIDDEN from:
- Editing any source files (.ts, .tsx, .js, .py, etc.)
- Editing any documentation (README, etc.)
- Fixing issues you find
- Running commands that modify the project source

You MAY ONLY:
- Read files and reports
- Create `.context-foundry/feedback.md` (human-readable report)
- Create `.context-foundry/learnings.json` (machine-readable patterns)

If you find issues, document them. The next build iteration will address them.

---

## Step 1: Analyze Artifacts (The "Review" Phase)

1. **Review Reports**: Read `architecture.md`, `build-log.md`, and `test-report.md`.
2. **Check Test Results**: Note any test failures and how they were resolved.
3. **View Screenshots**: Check `docs/screenshots/` for visual verification.
4. **Synthesize**: Compare the built result against the original requirements.

---

## Step 2: Create Feedback Report

Create `.context-foundry/feedback.md`:

```markdown

| Criterion | Status | Notes |
|-----------|--------|-------|

```

## Step 3: Capture Learnings (CRITICAL)

Create `.context-foundry/learnings.json` to capture patterns for future builds:

```json
{
  "version": "1.0",
  "project_name": "{project name}",
  "build_date": "{ISO date}",
  "verdict": "GO" or "NO-GO",

  "patterns_learned": [
    {
      "id": "{unique-id like 'nan-validation-required'}",
      "category": "bug-fix" | "best-practice" | "architecture" | "testing",
      "title": "{Short title}",
      "description": "{What was learned}",
      "trigger": "{What caused this to be discovered}",
      "solution": "{How it was resolved}",
      "severity": "critical" | "high" | "medium" | "low",
      "applicable_to": ["javascript", "typescript", "web-apps", etc.]
    }
  ],

  "issues_encountered": [
    {
      "id": "{unique-id}",
      "phase": "Architect" | "Builder" | "Test",
      "description": "{What went wrong}",
      "resolution": "{How it was fixed}",
      "iterations_to_fix": 1,
      "root_cause": "{Why it happened}"
    }
  ],

  "recommendations": [
    "{Recommendation for future builds}"
  ],

  "metrics": {
    "total_iterations": 1,
    "tests_passed": true,
    "phases_completed": ["Scout", "Architect", "Builder", "Test", "Screenshot", "Documentation", "Deploy"],
    "duration_seconds": 0
  }
}
```

### What to Capture as Patterns:

1. **Bug Fixes**: Any issue that required a fix iteration
   - Example: "NaN validation needed for calculateMercuryHeight()"

2. **Architecture Decisions**: Patterns that worked well
   - Example: "Separating API logic from UI logic improved testability"

3. **Testing Insights**: What made tests pass/fail
   - Example: "Floating-point comparison requires epsilon tolerance"

4. **Common Issues**: Problems likely to recur in similar projects
   - Example: "OpenWeatherMap API requires URL encoding for city names"
