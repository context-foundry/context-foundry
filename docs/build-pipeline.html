Knowmler x Context Foundry

From a piece of content to a working app

Knowmler's new build mode. Knowmler analyzes a video, PDF, or article, develops an app idea out of that analysis, and prototypes it. Once the idea is validated, Context Foundry builds it into a real, hosted application - it is the build engine behind the new "idea to app" mode.

hover any step to highlight it · the loop and tasks animate to show flow

Knowmler (understand & ideate) Context Foundry (build & host) Claude Opus Claude Sonnet
Knowmler · understand & ideate
1

Analyze the content

video / PDF / article

Knowmler ingests a source and produces a structured analysis: a summary, key concepts, action items, and cross-domain directions. This is Knowmler's core - making sense of dense material.

2

Develop an app idea from the analysis

App Builder

Instead of stopping at notes, Knowmler turns the analysis into a concrete product idea - the problem worth solving, who it is for, and the key features - drawn directly from what the content surfaced.

3

Generate a clickable prototype

approved visual target

The idea becomes a self-contained HTML prototype you can click through, so the look and the core workflow are shaped and agreed before any code is written.

4

Validate: vote and promote

Lab board

The idea goes to the community Lab board for votes and comments. A promoted idea is one with proven demand and an agreed visual target - the green light to build.

promoted idea + approved prototype → handed off to Context Foundry as the build spec
Context Foundry · build & host
5

Assemble the build inputs

SPEC.md + TASKS.md

Knowmler composes a SPEC (the brief, a required-capabilities list, and the full prototype inlined as a visual contract) and an ordered TASKS plan, then sends them to Context Foundry.

6

Submit the job

POST /v1/jobs

Context Foundry validates the inputs, queues the job, and launches one isolated, single-use builder container.

7

Builder container

runs each task in order

Every task moves through a five-stage agent pipeline. The active stage is highlighted as it cycles; the loop repeats for each task in the plan.

QUERY
Sonnet
Asks what it needs to know about the workspace.
›
RESEARCH
Sonnet
Reads the spec and files to gather context.
›
PLAN
Opus
Designs the implementation for this task.
›
BUILD
Opus
Writes the actual code.
›
AUDIT
Sonnet
Reviews its own work and fixes issues (the doubt loop).
QUERY → RESEARCH → PLAN → BUILD → AUDIT  ·  repeated per task
T1App shell & design system
T2Core screens & data
T3Primary interactive workflow
T4Secondary flows
T5Polish & persistence
T6Verify & finish
T7Package & host preview
↻ Knowmler polls progress every 15s → updates the page (10-95%)
8

Deploy the preview

isolated container

When the tasks pass, Context Foundry starts a separate preview container that serves the built application and returns a hosted URL.

9

Live application, back in Knowmler

clickable preview

Knowmler records the URL and the idea's page swaps to "Open the built app". What started as a piece of content is now a running application you can click through.
